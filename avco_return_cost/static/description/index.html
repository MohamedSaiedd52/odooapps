AVCO Vendor Return at Original Cost

Stop average-cost distortion when goods bought at different prices are returned to the vendor

The Problem

With the Average Cost (AVCO) method and no lot tracking, Odoo values a return to vendor at the current average cost — not at the price the returned goods were actually bought for.

Buy 10 pcs @ 100 and 10 pcs @ 200 (average = 150). Return the 200-batch: Odoo removes only 10 × 150 = 1,500 from stock, while the vendor credit note is 10 × 200 = 2,000. The remaining 10 cheap units stay valued at 1,500 instead of 1,000, the average cost stays 150 instead of 100, every later delivery books a wrong COGS, and a residue is stuck forever in the Stock Interim (Received) account.

The Fix

When a return is created from the original receipt (the standard Return button), Odoo already knows which receipt the goods came from. This module uses that link:

  • The return's valuation layer is booked at the original receipt cost (200 in the example), not the current average.
  • The average cost is realigned with the remaining stock (back to 100).
  • The journal entry of the return matches the vendor credit note, so the interim account nets to zero.
  • Later deliveries book the correct COGS.

Notes

  • Works with manual and automated (real-time) valuation; no configuration needed.
  • Applies only to returns created from the original document (Return button), where the origin link exists.
  • Partial returns are supported; returning the last units on hand always leaves exactly zero value.
  • Normal deliveries and FIFO / Standard products are not affected.
  • Covered by an automated test suite (6 scenarios, including the full bill / credit-note accounting flow).
