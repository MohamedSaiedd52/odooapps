Key Features

One single module the XLSX engine, controllers and report are all built in

Three output formats

Interactive on-screen view with Print Export buttons, a clean A4 PDF, and a formatted XLSX workbook.

 Excel export with openpyxl

The XLSX engine is rewritten on top of openpyxl no xlsxwriter, no report_xlsx / report_xlsx_helper dependencies.
One sheet per product

Select several products at once — each gets its own worksheet with filters, opening balance and a running balance column.

 Location aware

Pick any stock location — child locations are included automatically, and In / Out are computed against it.

Step-by-step Guide

1 Install the module

Open Apps, search for Stock Card Report and install it. The only requirement is the openpyxl Python library — no other Odoo module is needed.

2 Open the report from Inventory Reporting

Go to Inventory → Reporting → Stock Card. Access is controlled by the Stock Card Report User group added by the module.

3 Set your filters

In the wizard, choose the date range, one or more products and the location. Then pick your output: View (on screen), Export PDF or Export XLSX. Movements before the start date are summarized into the opening balance.

4 Review the report on screen

The View option renders the stock card right in the backend: date, reference (with source document), In, Out and the running Balance for every movement. Use the Print and Export buttons at the top to get the PDF or the Excel file without reopening the wizard.

5 Get a clean, formatted Excel file

Export XLSX downloads a workbook generated with openpyxl: a worksheet per product, highlighted headers, bordered cells, date and number formats, frozen header rows and print-ready page setup.

Technical notes

  • Single module the XLSX abstract engine, the xlsx report type, download controllers and the stock card report are all merged inside this module. The OCA report_xlsx report_xlsx_helper modules are not required.
  • openpyxl is the only Python dependency (pip install openpyxl); xlsxwriter is not used anywhere.
  • Report data is computed with a single SQL query over stock_move (state done), including child locations of the selected location.
  • Depends only on the core base, web and stock modules.
